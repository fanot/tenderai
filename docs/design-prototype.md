# Дизайн-прототип веб-сервиса TenderAI

Прототип реализован в интерактивном виде: `frontend/index.html` (рабочий интерфейс)
и `dist/tenderai-prototype.html` (автономная версия, открывается двойным кликом).
Настоящий документ описывает принятые проектные решения.

---

## 1. Кому и для чего

| Сценарий | Пользователь | Что должно занять минимум действий |
|---|---|---|
| Найти закупки по своему профилю | поставщик из МСП | один запрос обычными словами → релевантная выдача |
| Понять, подходит ли закупка | тендерный специалист | требования и сроки без открытия документации |
| Не пропустить дедлайн | оба | видимый срок и статус прямо в карточке выдачи |
| Оценить нишу | руководитель | распределение закупок по категориям и регионам |

Главный проектный принцип: **пользователь не должен знать язык закупок, чтобы начать**.
Поле поиска принимает обычную формулировку, а сервис показывает, что он из неё понял.

## 2. Дизайн-система

### Цвета

| Токен | Значение | Назначение |
|---|---|---|
| `--bg` | `#f6f7fb` | фон приложения |
| `--surface` | `#ffffff` | карточки, панели |
| `--ink` / `--text` | `#0f172a` | основной текст |
| `--muted` | `#64748b` | вторичный текст, подписи |
| `--border` | `#e4e7ef` | границы |
| `--accent` | `#6d28d9` | основной акцент, действия |
| `--accent-2` | `#8b5cf6` | градиенты, вторичный акцент |
| `--accent-soft` | `#f2edfe` | фон акцентных плашек |
| `--ok` | `#0d9488` | открытый приём заявок |
| `--warn` | `#d97706` | предупреждения ассистента |
| `--danger` | `#dc2626` | горящий дедлайн |

Акцентный фиолетовый выбран для визуальной связи с партнёрскими программами
поддержки технологического предпринимательства.

### Типографика и сетка

* Шрифт: Inter / системный sans-serif; базовый размер 15 px, интерлиньяж 1.55.
* Заголовки — с отрицательным трекингом (`-0.02…-0.03em`) для плотного вида.
* Скругления: 14 px у карточек, 10–11 px у элементов управления.
* Тени мягкие двухслойные — карточка отделяется от фона, но не «висит».
* Основная сетка экрана поиска: `246px | 1fr | 380px` (фильтры, выдача, ассистент).
  При ширине < 1180 px скрывается панель ассистента, < 820 px — панель фильтров.

## 3. Экраны

### 3.1. Поиск (главный экран)

```
┌──────────────────────────────────────────────────────────────────┐
│ TenderAI            Поиск · Аналитика · О сервисе      режим: API│
├──────────────────────────────────────────────────────────────────┤
│ Умный поиск тендеров                                             │
│ [ разработка информационной системы в Москве до 20 млн  ] [Найти]│
│ (подсказки-чипы с готовыми запросами)                            │
│ распознано: [44-ФЗ] [г. Москва] [НМЦК до 20 000 000 ₽] [ИТ и ПО] │
├───────────┬──────────────────────────────┬───────────────────────┤
│ ФИЛЬТРЫ   │ Найдено 4 закупки · 86 мс    │ RAG-ассистент         │
│ закон     │ ┌──────────────────────────┐ │ ┌───────────────────┐ │
│ категория │ │ 44-ФЗ · Подача заявок    │ │ │ вопрос            │ │
│ регион    │ │ Название закупки         │ │ │ ответ со ссылками │ │
│ статус    │ │ заказчик · регион · срок │ │ │ [1] источник      │ │
│ НМЦК      │ │ 1 350 000 ₽              │ │ │ [2] источник      │ │
│ ☐ приём   │ │ почему в подборке  score │ │ └───────────────────┘ │
│ ☐ СМП     │ └──────────────────────────┘ │ [ поле ввода ]     → │
└───────────┴──────────────────────────────┴───────────────────────┘
```

Проектные решения:

* **Строка «распознано»** — ключевой элемент доверия. Пользователь видит, как система
  поняла его запрос, и может поправить фильтр вручную, не переформулируя фразу.
* **Явные фильтры важнее распознанных.** Если пользователь выбрал закон в панели,
  он перекрывает закон, упомянутый в тексте запроса.
* **«Почему в подборке»** — под каждой карточкой перечислены причины попадания
  (совпадение по категории, региону, открытый приём заявок, близкий дедлайн).
  Выдача перестаёт быть «чёрным ящиком».
* **Числовая оценка релевантности** показана моноширинным шрифтом мелким кеглем —
  полезна при отладке и демонстрации, не мешает основному сценарию.
* **Статус и срок вынесены в плашки** вверху карточки: горящий дедлайн (≤ 7 дней)
  подсвечивается красным.

### 3.2. Карточка закупки (модальное окно)

Полные реквизиты (реестровый номер со ссылкой в ЕИС, заказчик и ИНН, ОКПД2, способ
определения поставщика, площадка, обеспечения, даты), список требований к участникам,
преференции и ограничения, описание, блок похожих закупок и кнопка «Спросить ассистента
об этой закупке» — переход из просмотра в диалог без потери контекста.

### 3.3. RAG-ассистент

* Диалог закреплён справа и не перекрывает выдачу — пользователь одновременно видит
  и ответ, и список закупок.
* Ссылки `[n]` в тексте ответа кликабельны и открывают карточку соответствующей закупки.
* Под ответом — карточки источников с названием, разделом и реестровым номером.
* Предупреждения guardrail выводятся отдельной строкой оранжевым.
* Индикатор набора текста показывает, что запрос обрабатывается.

### 3.4. Аналитика

Пять KPI-плиток (всего закупок, идёт приём заявок, суммарная и средняя НМЦК, доля
закупок для СМП) и четыре панели: распределение по категориям, по регионам, по законам
с объёмом НМЦК, а также список закупок, закрывающихся в ближайшую неделю (кликабельный).

Горизонтальные полосы вместо круговых диаграмм: категории и регионы — это ранжированные
списки, а сравнение длин полос читается точнее, чем сравнение секторов.

### 3.5. О сервисе

Описание конвейера обработки запроса и технологического стека — экран для демонстрации
проекта и для новых участников команды.

## 4. Состояния интерфейса

| Состояние | Как показано |
|---|---|
| Загрузка выдачи | скелетоны карточек с анимацией |
| Пустая выдача | подсказка, что именно ослабить (бюджет, регион) |
| Ответ ассистента формируется | анимированные точки в пузыре сообщения |
| Backend недоступен | переключение в офлайн-режим, индикатор «режим: офлайн-демо» |
| Нет источников у ответа | прямое сообщение, что закупок не найдено |

Индикатор режима в шапке всегда показывает, откуда взяты данные — это снимает
двусмысленность при демонстрации автономной версии.

---

## 5. Доступность и адаптивность

* Контраст основного текста к фону — 15.9:1, вторичного — 4.9:1 (AA соблюдён).
* Все интерактивные элементы — нативные `button`, `select`, `input`: работает
  клавиатурная навигация и экранные читалки.
* Модальное окно закрывается по `Esc` и клику по подложке.
* SVG-логотипы партнёров снабжены `role="img"` и `aria-label`.
* Три брейкпоинта: 1180 px (скрывается ассистент), 900 px (перестраиваются панели
  аналитики), 820 px (скрываются фильтры, одноколоночная вёрстка).

---

## 6. Технические ограничения прототипа

Интерфейс намеренно собран без сборщика и внешних зависимостей: один HTML-файл,
нативный CSS с переменными и vanilla JS. Это даёт три преимущества для прототипа —
мгновенный запуск без `npm install`, возможность показать демо одним файлом и
отсутствие расхождений между «дизайном» и «реализацией». При переходе в продуктив
дизайн-система переносится в компонентную библиотеку (React + CSS-переменные
сохраняются как есть).
